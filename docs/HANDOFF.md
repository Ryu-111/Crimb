- 数値（精度など）は、測った方法と一緒に書く。測っていない数値は書かない
- ユーザーの動画や個人データの中身はここに書かない（置き場所だけ書く）

### 精度改善の状況

ユーザーの実際の登攀動画 2 本で測った（手元のみ。動画はリポジトリに入れない）。

- 動画 a: 紫の課題。19 秒。人が画面に小さく写る。壁が暗い灰色で、服は黒
- 動画 b: ピンクの課題。47 秒。カメラを手で持って追いかけている

| 指標 | a | b |
|---|---|---|
| 姿勢の検出率（いずれかの人を検出したコマ） | 45% | 100% |
| 正しい人を検出したコマ（腰が目視の位置から 8%×6% 以内） | **7%** | 89% |
| 手の移動数（目視の範囲） | 1（6〜8） | 11（8〜14） |
| 足の移動数（目視の範囲） | 2（7〜10） | 11（10〜18） |
| 課題の再現率（目視で数えた手足の接触を拾えた割合） | **0/4** | 3/4 |
| 接触の適合率（拾った接触のうち正しいもの） | – | **7/16 = 44%** |

分かった原因:

1. **a は人の検出に失敗している**（主因）
   - 全身が画面の 15% 程度と小さいため、MediaPipe が人を見つけられない。
   - 1〜7 秒は壁のホールドの塊を人と誤検出し、VIDEO モードがそれを追い続けた。
   - 8〜17 秒は検出なし。
   - 全体を 1 枚で IMAGE モードにかけても、検出は 0 だった。
2. **b はカメラが動くので、手足とホールドの位置がずれる**
   - 手持ちで追いかけて撮っているため、映る範囲が上下に最大で画面の約 14% 動く。
   - ホールドは 1 コマ（壁の写真）の座標なので、足の接触が別のホールドに付く。
3. 歩いて壁に近づく場面（登る前）にも、接触を拾ってしまう

打ち手と結果:

1. **カメラの動きの補正**（実装済み）
   - 解析中にコマごとの壁のずれを記録する（`PoseTrack.camera`）。`src/analysis/camera.ts` の `trackCamera` / `stabilize` で行う。
   - 課題の 3D 表示では、手足を壁の写真のコマの座標に直してから接触を判定する。
   - b の目視の正解と比べた結果（記録済みの姿勢にずれを当てて、手元で計算）:
     - 課題の再現率: 4/5 → **5/5**
     - 接触の適合率: 62% → **86%**
     - b の正解には、目視で確認した「左足をハリボテに乗せている」区間を足してある。
   - アプリ上で再計測しても同じ値になった（Playwright で b を解析。`camera` は 701 コマすべてで記録されていた）。
   - b の手と足の移動数は、補正の前後で変わらない（11 / 11）。補正は課題の 3D 表示にだけ使っている。
2. **a の人の検出**（YOLO-pose で解決の見込み。組み込みは上の「進行中」）
   - 手元の検証（python + onnxruntime、YOLO11n-pose、人の周りを 320 で切り抜く方式）では、MediaPipe と合わせると次のようになった。

     | 動画 | 手の移動数（目視） | 足の移動数（目視） |
     |---|---|---|
     | a | **5**（6〜8） | **7**（7〜10） |
     | b | 11（8〜14） | 9（10〜18） |

     | eric | 13（12〜16） | 13（10〜15） |

     - YOLO だけだと、eric（強い傾斜で、腕を上げた体勢）の検出が 74% に落ちる。そのため MediaPipe と合わせる形にした。
